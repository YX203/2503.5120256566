# 图书馆借阅管理系统（面向对象程序设计 C++）

西南科技大学《面向对象程序设计（C++）》课程实验，实验一 ~ 实验六。
（基础题目三：图书馆借阅管理系统，按实验指导书逐次进阶实现）

## 一、项目结构

## 二、类的层次

```
Resource（抽象基类）
 ├── Book        普通图书   借期 30 天，逾期 0.2 元/天
 ├── Magazine    杂志       借期  7 天，逾期 0.5 元/天
 └── EBook       电子资源   借期  3 天，逾期 1.0 元/天（不限份数）

Reader（抽象基类）
 ├── Student     学生   默认最多借 5 本
 └── Teacher     教师   默认最多借 10 本

PtrCollection<T>（类模板，T = Resource 或 Reader）
 └── 内部：std::vector<T*>   ← 一个容器装下多种派生类对象
      ↑
   Library（组合类）同时拥有 PtrCollection<Resource> 与 PtrCollection<Reader>
```

## 三、知识点覆盖

**实验一　类与对象**
- 类的设计、`private / protected / public` 访问控制
- 默认构造函数 + 重载构造函数；构造函数的初始化列表
- 数据成员合法性校验（ISBN 13 位、价格/页数/数量非负、年级 1~5、最大借阅数上限等）
- 初始化、修改（set）、获取（get）、输出（print）基本操作
- 多文件组织；单一职责原则（容器只管持有与释放，`Library` 只管业务）

**实验二　组合关系与依赖关系**
- 组合：`Library` 包含 `PtrCollection<Resource>` 与 `PtrCollection<Reader>`；
  `Reader` 包含 `std::vector<BorrowRecord>`（对象成员 => has-a）
- 依赖：`Reader::borrowResource(Resource& res)` 以另一个类的对象引用作参数，
  一次调用同时改变借阅人与资源双方状态
- 构造函数的初始化列表、析构函数统一释放资源

**实验三　继承与派生**
- 公有继承、派生类构造函数调用基类构造函数
- 派生类新增自己的数据成员与成员函数
- 资源的增加、删除、**增加数量**、**减少数量**、单条查询、全部显示
- `new` / `delete` 的使用

**实验四　多态性与虚函数**
- 基类中声明**纯虚函数** → `Resource`、`Reader` 成为抽象类
- 基类**虚析构函数**
- 用**基类指针容器**统一管理不同派生类对象，通过基类指针调用虚函数
- 派生类重写虚函数，同名函数表现出不同行为（借期、罚金、显示内容、
  电子资源不限份数）
- **操作符重载**：`operator<<`、`operator==`、`operator<`

**实验五　模板和 vector 容器的使用**
- **类模板** `PtrCollection<T>`：一组结构相同、元素类型不同的类，用模板抽象一次
- **成员函数模板 + 可变参数模板**：`emplaceNew<Derived>(args...)`，
  `std::forward` 完美转发，把参数直接交给派生类构造函数
- **函数模板**：`readValue<T>()` 统一处理 `int / double / string` 的键盘输入
- **vector 全部常用接口**：
  `push_back`、`emplace_back`、`size`、`capacity`、`empty`、
  `begin`、`end`、`back`、`at`、`operator[]`、`erase`（单元素 / 区间）、
  `clear`、范围 for、迭代器遍历
- **彻底取代定长数组**：原来的 `Resource* resources[100]`、`Reader* readers[100]`、
  `BorrowRecord records[50]` 全部换成 vector，容量按需增长，不再有"已达上限"
- 容器析构时 `clear` 并 `delete`，做到"最后清空 vector 回收资源"

**实验六　输入、输出流**
- `cin` / `cout` 处理键盘与屏幕，`fstream` 头文件里的 `ofstream` / `ifstream` 处理磁盘文件
- **对象的保存** = 把对象相应成员变量的值写进文件；**对象的读取** = 按文件数据重新 `new` 出对象
- 存盘用**虚函数** `Resource::saveTo()` / `Reader::saveTo()`：基类写公共字段，
  派生类重写后追加自己的字段 —— 一个容器里混装 `Book / Magazine / EBook` 也能一次写完；
  这正是实验六思考题"如何既保存基类对象又保存派生类对象"的一半答案
- 读盘用**类型标记 + 分支 new**：`ifstream` 逐行 `getline`，按行首的"普通图书 / 杂志 / 电子资源"
  决定构造哪个派生类，再 `setStock` 还原可借数量 —— 这是思考题的另一半答案
- `open / close / is_open`、`getline`、`<<` 插入与 `>>` 提取、`ostringstream` 缓冲拼行
- 启动时自动读盘、退出时自动存盘，实现"重启应用程序后数据还在"

## 五、实验五的两个思考题（代码里都有对照答案）

**1. vector 里放对象和放对象指针有什么区别？**

| 对比项 | `vector<对象>`（如 `Reader` 的 `vector<BorrowRecord> records`） | `vector<对象指针>`（如 `PtrCollection<Resource>`） |
|---|---|---|
| 内存 | 对象本身连续存放在容器里 | 容器只存指针，对象散落在堆上 |
| 生命周期 | 跟随容器，`clear`/`erase` 自动析构，无泄漏风险 | 容器销毁时**必须**自己 `delete`，否则泄漏 |
| 拷贝语义 | `push_back` 会拷贝对象，元素必须可拷贝 | 只拷贝指针，代价小，但两个容器可能指向同一对象（本项目禁止容器拷贝） |
| 多态 | ✗ 按值存放派生类会被"切片"，只能存同一类型 | ✓ 基类指针可指向任意派生类，虚函数正常生效 |
| 动态增删代价 | `erase` 中间元素要搬移对象，代价较大 | `erase` 只搬移指针，代价小 |
| 适用场景 | 生命周期明确的部件，如借阅记录 | 需要继承体系与多态的对象集合，如馆藏资源、借阅人 |

**2. 基类和派生类的对象能否放在一个 vector 底下？**

可以，但**元素类型必须是基类指针**（`vector<Resource*>`，本项目即 `PtrCollection<Resource>`）。
把 `Book / Magazine / EBook` 的地址统一存进去，遍历时通过基类指针调用虚函数，
各自的 `print`、`getLendDays`、`getFinePerDay`、`borrowOne` 就会执行派生类版本。
两个前提不能少：
1. 基类要有**虚析构函数**，否则 `delete` 基类指针时派生类部分不会析构；
2. 容器销毁时必须逐个 `delete`（本项目统一由 `PtrCollection::clearAll()` 负责）。

## 六、编译与运行

用 Visual Studio 打开 `面向对象程序设计.slnx`（或直接打开 `.vcxproj`），
选择 `Debug | x64`，按 `F5` 运行。（命令行也可：`g++ -std=c++17 *.cpp -o lib`）

源文件保存为 **UTF-8 with BOM**，在中文 Windows 控制台下可直接正常显示中文。

### 与指导书"项目答辩（设计报告2）· 题目3"需求的对应关系

| 指导书需求 | 实现的菜单项 |
|---|---|
| 添加借阅人信息 | 8 添加借阅人（学生 / 教师），编号重复会被拒绝 |
| **修改借阅人信息** | **27**（姓名 / 院系 / 最大借阅数量 / 专业年级 / 职称学院） |
| 处理借阅信息，借阅功能 | 10 借阅资源 |
| 处理还书信息，归还功能 | 11 归还资源（自动结算逾期罚金） |
| 添加图书或资源信息 | 2 添加新资源（三种资源类型分别录入专属字段） |
| **修改图书或资源信息** | **26**（名称 / 出版社 / 价格 / 总量 / ISBN 作者页数 / 期号主编 / 大小链接） |
| 查看图书信息 | 1 显示全部、6 查询某一资源详情、7 按价格排序 |
| 查询以上信息 | 6 查资源、**28** 查借阅人（按编号或姓名） |
| 提供用户管理功能 | 8 添加、27 修改、28 查询、9 显示全部、20 注销、21 清空 |
| STL（vector）组织对象 | `PtrCollection<T>` 内部 `std::vector<T*>`，16~19 有交互演示 |
| 文件输入输出流 | 22 存盘、23 读取、24 导报表、25 查看文件；启动自动读、退出自动存 |

两个"修改"功能的实现要点：条码 / 编号是主键不可改；改馆藏总量时按差值调用
`addStock / reduceStock`，保证 `stock` 与 `totalCount` 同步；改派生类专属字段时
用 `dynamic_cast` 向下转型 —— 手里只有 `Resource*` / `Reader*`，转型成功才知道该改哪些字段。

## 八、演示建议（答辩/验收路径）

1. 先跑 **1 / 9** 看多态输出：同一个容器里 `Book`、`Magazine`、`EBook`、
   `Student`、`Teacher` 各按自己的格式显示。
2. 跑 **10 → 15（40 天）→ 12 → 11**：借书 → 推进时间 → 看逾期汇总 → 归还，
   罚金按各资源的日罚金标准自动计算。
3. 跑 **16**：现场输入书名和价格，观察 `push_back / emplace_back` 时
   `size` 与 `capacity` 的变化（1、2、4、8 … 成倍增长），再看 `erase` 删除中间元素、
   `clear` 清空后容量仍保留。
4. 跑 **17 / 18**：说明"一个 vector 装多种派生类"靠的是基类指针 + 虚函数，
   并用迭代器统计各类型的种数与册数。
5. 跑 **19 / 20 / 21**：分别演示 `vector::erase(区间)`、`vector::erase(位置)`、
   `vector::clear` 三种删除方式。
6. 跑 **22 → 25 → 0 退出 → 重新运行 → 1 / 13**：存盘 → 看文件内容 → 重启后数据还在，
   说明"对象的保存与读取"确实落到了磁盘上。**24** 顺便导出一份 `report.txt` 可直接交作业。
